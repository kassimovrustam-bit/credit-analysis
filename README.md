# Система кредитного анализа групп компаний

Внутренняя веб-система подготовки резюме по проектам финансирования: реестр проектов, отчетность РСБУ, коэффициенты, NPV/IRR/DSCR, проверки учредителей, риски, скоринг и выгрузка резюме в Word.

## Требования

- Python 3.10+
- Node.js 20+ и npm (только для сборки фронтенда)
- SQLite входит в Python, отдельная БД не нужна

## Быстрый запуск

Команды выполняются из каталога `outputs/credit-analysis/`.

### 1. Backend

```bash
python -m pip install -r backend/requirements.txt
```

```bash
python -m uvicorn --app-dir backend app.main:app --host 127.0.0.1 --port 8000
```

API: `http://127.0.0.1:8000/api`, документация: `http://127.0.0.1:8000/docs`.

### 2. Frontend для разработки

```bash
cd frontend
```

```bash
npm install
```

```bash
npm run dev
```

Интерфейс разработки: `http://127.0.0.1:5173`. Backend должен быть запущен на порту 8000.

### 3. Production-сборка

```bash
cd frontend
```

```bash
npm run build
```

После сборки перезапустите backend. Он раздает интерфейс из `frontend/dist`:

```bash
python -m uvicorn --app-dir backend app.main:app --host 0.0.0.0 --port 8000
```

## Проверка и демонстрационные данные

Из корня проекта:

```bash
python -I scripts/selftest.py
```

Самотест проверяет парсер форм, коэффициенты, NPV/IRR, платежные графики, DSCR, парсер ПКБ и скоринг (41 проверка).

```bash
python -I scripts/seed_demo.py
```

Сидер создает полный демо-проект через тот же API и ту же БД, которую использует сервер. Повторный запуск пересоздает демо-проект. Для него также формируются скоринг и `.docx`.

## Хранение данных

- База: `backend/credit_analysis.db` (при переходе на PostgreSQL меняется `DATABASE_URL` в `backend/app/config.py`).
- Файлы: `backend/storage/project_<id>/`.
- Автодокументация API: `/docs`.

## Модель скоринга

Финансы группы — 40%, проект — 30%, учредители — 20%, риски — 10%. Вердикты: не менее 70 — рекомендуется; 50–70 — возможно при условиях; менее 50 — не рекомендуется. Пороги коэффициентов находятся в `backend/app/services/ratios.py` и подлежат калибровке на пилоте.

Результат эвристического разбора отчета ПКБ обязательно сверяется аналитиком с оригиналом. OCR сканов, запросы к внешним госбазам и аутентификация в MVP не входят; система предназначена только для изолированной внутренней сети.
